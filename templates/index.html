Why would a result ever be “unknown”? …
  • Greylisting / rate limits. Many servers answer a first-contact probe with a temporary 4xx “try later” instead of a verdict.
  • Catch-all domains. Some domains accept every local part, so the server's “OK” cannot prove the specific mailbox exists. The checker probes with a random name to detect this and reports those unknown.
  • Refused verification. Big providers (Yahoo, Apple, Zoho…) often reject recipient verification on purpose, or bounce the probe for IP-reputation/policy reasons.
  • Environment limits. Hosting platforms that block outbound SMTP (port 25) reduce this checker to syntax + DNS; the banner at the top tells you if that applies here.

No message is ever sent: the SMTP session stops right after RCPT TO and always quits before DATA. Results are best-effort estimates, not guarantees — servers can still bounce accepted mail later.

Local checks: syntax → DNS MX → disposable-domain hint → SMTP RCPT probe (never sends mail). See the README for hosting notes and limitations.
